# AGENTS.md

## What this is

`@blimmer/cdk-github-oidc` is an AWS CDK construct library for setting up GitHub
Actions ↔ AWS authentication via OpenID Connect. It exists because the
lower-level `aws-iam.OpenIdConnectProvider` and `OpenIdConnectPrincipal`
primitives require hand-crafting IAM trust conditions on the `sub` claim, which
is verbose and error-prone. This library exposes typed, ergonomic constructs
(`GithubActionsIdentityProvider`, `GithubActionsRole`) and a composable `*Filter`
hierarchy that produces those trust conditions for you. It was inspired by the
now-unmaintained `aws-cdk-github-oidc`. See `README.md` for the consumer-facing
API.

## This is a projen project

`.projenrc.ts` is the source of truth for repo configuration. Any file with a
`~~ Generated by projen` header is regenerated by projen — hand-edits will be
overwritten on the next synth.

To change a generated file (`.eslintrc.json`, `.gitignore`, `.mergify.yml`,
`tsconfig.dev.json`, GitHub workflows, most of `package.json`, etc.):

1. Edit `.projenrc.ts`.
2. Run `pnpm exec projen` to regenerate.

`pnpm` is required — the lockfile is `pnpm-lock.yaml` and projen is configured
for pnpm.

## Layout

- `src/` — library source. Public surface is re-exported from `src/index.ts`.
- `src/filters/` — subject filter classes. Each implements
  `IGithubActionOidcFilter` and contributes to the IAM trust policy via
  `toSubject()`.
- `src/generated/` — output of `@mrgrain/jsii-struct-builder`. Hand-edits are
  overwritten; change the `ProjenStruct` block in `.projenrc.ts` instead.
- `test/` — Jest tests, mirroring `src/`.

## Design notes

- `GithubActionsRole` **extends** the CDK `Role`. It *is* a Role, so consumers
  use `grant*` / `addToPolicy` directly on it. Don't replicate IAM APIs on the
  wrapper.
- `GithubActionsIdentityProvider` is a singleton per AWS account. Consumers
  either `new` it (in the stack that creates it) or call
  `GithubActionsIdentityProvider.fromAccount(scope)` to import an existing one.
  Don't introduce APIs that would produce more than one per account.
- The library is published via **jsii** to npm and PyPI. Public API changes are
  constrained by jsii's type and compatibility rules; `projen compat` enforces
  backward compatibility against the last published version. Run the full build
  locally before assuming an API change is safe.

## Commands

| Command            | Purpose                                                                |
| ------------------ | ---------------------------------------------------------------------- |
| `pnpm install`     | Install dependencies.                                                  |
| `pnpm exec projen` | Regenerate projen-managed files after editing `.projenrc.ts`.          |
| `pnpm build`       | Full build: compile, test, package, docgen. This is what CI runs.      |
| `pnpm test`        | Run Jest tests only.                                                   |
| `pnpm eslint`      | Lint.                                                                  |

## Commit conventions

Conventional Commits. Only `feat:` and `fix:` produce releases (configured via
`ReleasableCommits.featuresAndFixes()` in `.projenrc.ts`); `chore:` / `docs:` /
`refactor:` and friends are no-release.
